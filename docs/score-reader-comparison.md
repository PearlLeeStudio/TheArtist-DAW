# 악보 분석: Local / Meta / Hybrid 1회 / Hybrid 2회

동일한 5개 PDF에서 실행한 소규모 진단 비교다. **Hybrid 1회는 4/5개를
완료했지만, 2회는 3/5개였다. 추가 검토가 항상 정확도를 높이지 않았다.**
읽기 성공, 마디 수 일치, 음표 근거, 화성 해석은 별도로 평가했다.

## 네 조건과 결과

| 조건 | 실제 경로 | 완전한 분석 반환 | 자작 악보의 기준 코드 마디 일치 | 자작 악보의 읽은 음고집합 일치 | 파일당 평균 시간 | 5개 입력 비용 |
|---|---|---:|---:|---:|---:|---:|
| Local only | 벡터 PDF 판독 → 음표 화성 규칙 → 필요한 빈 마디에 F1 제안 | 3/5 | 7/7 | 8/8 | 0.592초 | $0 |
| Meta only | 원본 PDF → Standard Muse Spark 1회 | 3/5 | 6/7 | 4/8 | 26.203초 | $0.10659330 |
| Hybrid 1회 | 같은 Local 결과 + 원본 → Meta 1회 → 비교 | 4/5 | 7/7 | 8/8 | 24.507초 | $0.09157425 |
| Hybrid 2회 | Hybrid 1회의 결과 + 원본 + 로컬 근거 → Meta 재검토 1회 → 비교 | 3/5 | 6/7 | 7/8 | 42.329초 | $0.16518625 |

시간은 실패를 포함한다. Hybrid 시간에는 로컬 시간도 들어가며, 2회 조건은
첫 검토와 재검토를 합친 값이다. 2회 조건은 실제로 얻은 Hybrid 1회 결과를
공유했다. 따라서 표의 비용 열을 전부 합하면 중복된다. 실제 배치 합계는
**14회 호출, $0.27177955, 미정산 예약 $0**이다. 첫 검토가 실패한 Bach의
두 번째 호출은 실행하지 않았으며, 해당 2회 조건도 실패로 집계했다.

`Local model only`라는 말은 여기서 **제품의 로컬 분석 경로**를 뜻한다.
판독기는 Music Transformer가 아니다. F1은 읽힌 음이 있으나 화성이 빈
마디에만 쓰였으며, 이 실험에서 실제 호출된 자체 모델은 `ft_f1` 하나다.
18개 체크포인트의 성능 비교나 새 파인튜닝 평가가 아니다.

## 입력과 독립 기준

| 입력 | 마디 | 기준 | Local | Meta | Hybrid 1 | Hybrid 2 |
|---|---:|---|---|---|---|---|
| 자작 C 장3화음 | 1 | 생성한 C4/E4/G4, C, 4/4 | 완료 | 화성 반환 실패 | 완료 | 재검토 실패 |
| 자작 혼합 코드 수 | 4 | C / Dm·G7 / C / N.C. | 완료 | 완료 | 완료 | 완료 |
| 자작 문맥 빈칸 | 3 | C / D4 단음 / G7. 가운데 화성 정답은 지정하지 않음 | 완료 | 완료 | 완료 | 완료 |
| Mozart K.2, Mutopia | 24 | LilyPond의 F major, 3/4, 작성 순서 24마디 | 로컬 형식 미지원 | 완료 | 완료 | 완료 |
| Bach BWV 846, Mutopia | 35 | LilyPond의 C major, 4/4, 35마디; MIDI 음표 집합 | 로컬 형식 미지원 | 출력 한도 실패 | 출력 한도 실패 | 첫 검토 실패로 미실행 |

자작 악보는 저장소 MIT 라이선스의 독립 벡터 그림이다.
[생성기](../backend/tests/vector_score_fixture.py)의 입력으로 기준을 정했으며,
모델 응답을 정답으로 삼지 않았다. 실제 판본의 출처·라이선스·PDF/MIDI/LilyPond
해시는 [sources.json](../experiments/external_eval/sources.json)에 있다.
[Mozart K.2](https://www.mutopiaproject.org/cgibin/piece-info.cgi?id=1770)와
[Bach BWV 846](https://www.mutopiaproject.org/cgibin/piece-info.cgi?id=5)는
manifest에 Public Domain으로 기록된 판본을 사용했다. 개인 악보는 포함하지 않았다.

코드 일치는 순서·개수·루트·코드 음고집합을 비교한다. 같은 화음을 한 번
쓴 경우와 두 번 쓴 경우를 같다고 세지 않는다. N.C.는 명시적 `noChord`도
맞아야 한다. 이 지표는 슬래시 베이스의 정확도나 코드 배치 시점을 평가하지 않는다.
음표 지표는 `notes`의 음고집합을 독립 기준과 비교하며 옥타브·리듬·성부는
평가하지 않는다. 제안한 코드에서 음표를 역산하지 않는다.

Bach의 35마디는 원 MIDI에서 추출한 음고집합 기준이 있지만, 모든 조건에서
완전한 결과를 얻지 못했다. 따라서 전체 43개 음표 기준 마디를 실패 포함으로
집계하면 Local 8/43, Meta 4/43, Hybrid 1회 8/43, Hybrid 2회 7/43이다.
이 낮은 수치를 “반환한 음표의 정확도”로 오해하지 않아야 한다. 판독 범위와
출력 한도 실패가 함께 반영된 값이다. Mozart/Bach의 전문가 화성 정답은
확보하지 않았으므로 실제 곡의 코드 정확도는 산출하지 않았다.

## 무엇이 달랐나

- **한 마디 1코드와 2코드:** 혼합 코드 수 사례는 모두 4/4마디를 맞혔다.
  편집기에서 단일 코드를 두 슬롯에 유지하는 것과 원본의 두 코드 변화를
  구분해야 한다. N.C.를 unresolved로 취급하지 않았다.
- **문맥 빈칸:** 가운데 D4에 Local은 `Dsus4 → Dmaj`, Meta는 `G`,
  Hybrid 1회와 2회는 `Dm`을 제안했다. 어느 하나를 원곡 정답이라고 채점하지
  않았다. Meta only는 이 사례의 음표 집합을 0/3마디, 두 Hybrid는 3/3마디
  맞혔다. 자체 모델은 조성을 G major로 추정했으므로 조성 선택 자체도 검토
  대상이다. 사용자가 확정한 조성을 무시해도 된다는 근거가 아니다.
- **반복 검토의 퇴행:** C 장3화음은 첫 Hybrid에서 반환됐지만 재검토에서는
  사용할 화성을 반환하지 못했다. 이전 응답을 다시 보여 주는 것은 독립
  검증이 아니며 오판을 반복하거나 새로운 오판을 만들 수 있다.
- **출력 한도:** Bach의 Meta only와 첫 Hybrid는 각각 출력 토큰 8192개를
  모두 사용했다. reasoning 토큰도 이 한도에 포함된다. JSON 완결에 실패한
  출력을 성공으로 열지 않았다. 현재 원본 전체 읽기 경로의 명확한 제한이다.
- **구조와 조성:** 기준이 있는 3개 입력의 조성 일치는 네 조건 모두 1/3이다.
  단순 자작 C 화음의 조성을 유일하게 확정할 수 있다는 뜻은 아니다.
  마디 수/박자 일치는 각 조건의 반환 완료 수와 같았으며, 이것만으로 화성이
  정확하다고 주장할 수 없다.

현재 결과는 **기본 로컬 + 선택적 Hybrid 1회**를 유지하고, 2회는 평가용으로
남겨 둘 근거다. 긴 재즈 악보의 일반 정확도나 청음 품질은 이 표로 입증되지
않는다. 128마디 초과 로컬 결과의 정상 열기와 문맥 보완 코드는
[분석 계약](score-analysis.md#why-a-passage-can-remain-unresolved)에 별도로 설명했다.

## 재현과 제한

[실행기](../agent/compare_score_readers.py)와
[전체 응답·오류·request ID·토큰·비용](../experiments/external_eval/four-reader-results.json)을
함께 보존한다. `MODEL_API_KEY`가 설정된 백엔드 환경에서 실행기의 `--backend`,
`--sources`, `--output`, `--ledger`에 각각 절대경로를 지정한다. sources는 기존
외부 평가의 해시가 맞는 PDF/MIDI와 `sources.json`을 담은 폴더다. 기존 결과는
덮어쓰지 않는다. 로컬 워크스페이스에서는 `scripts/dev.sh py` 래퍼로 실행한다.

Standard `muse-spark-1.3`, 호출당 75초·8192 출력 토큰·$1.35 상한,
최대 15회·별도 영속 장부 $5 한도·자동 재시도 없음으로 실행했다. 로컬 F1
샘플링 seed는 1380이며 Meta는 확률적 단일 실행이다. 조건당 반복 측정이나
유의성 검정은 하지 않았다. API/캐시 지연 때문에 시간 차이를 모델 고유의
속도 차이라고 해석하지 않는다. 특정 악보의 성공만 골라 재시도해서 표를
채우지 않았으며, 실패한 원자료도 그대로 남긴다.
